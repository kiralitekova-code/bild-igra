# Game Architecture Patterns

Read this file only when the core skill needs broader structural guidance.

## Shared Patterns

1. Separate simulation from presentation.
2. Define input as actions, not raw device reads.
3. Keep asset and data boundaries explicit.
4. Keep save, debug, and performance boundaries up front.
5. Keep state ownership narrow and obvious.
6. Prefer the smallest coordination surface that still keeps systems decoupled.
